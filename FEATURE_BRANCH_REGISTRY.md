## 1. Branching Model, Collaborator Alignment & Unified `extendable*` (`E*`) Suite

To maintain maximum traceability, testbed stability, and clean upstream Pull Request preparation without stepping on collaborator branches or Jenkins jobs:

1. **Clean Upstream PR Branches (`feat/rep159-*`, `feature/rep159-*`)**:
   - Cut directly from upstream **`master`/`main`** (or directly stacked on Jose Luis Rivero's `jrivero` commits) with **zero Dockerfile tarball `pip` hacks or fork URLs**.
   - Strictly enforce canonical lowercase template placeholders (`{distro}`, `{package}`, `{origin_distro}`) and semantic branch names without `stage` prefixes.
2. **Testbed Feature Branches (`feat/binary-naming-rule`, `feat/extendable-workspace`)**:
   - Where downstream tools (`rosdep`, `ros_buildfarm`) depend on unreleased `rosdistro` / `rosdep` features, active testbed branches temporarily carry **pre-release bootstrap overrides** (`pip3 install ...tar.gz` in `*.Dockerfile.em` and fork git URLs) so Jenkins CI and release pipelines on `build.test.ros2.org` can run end-to-end before upstream PyPI / `ros_bootstrap` APT releases exist.
3. **Collaborator & Namespace Isolation (`jrivero` & `cargotest`)**:
   - Collaborator branches (`rep159`, `rep159-child-ros-workspace`, `rep159-parent-chain`, `kmom88`), distributions (`upstream`, `srcext`, `binext`, `cargotest`), and Jenkins jobs (`U*`, `S*`, `B*`, `C*`) are never modified or overwritten.
   - Instead, our clean PR branches cherry-pick and stack directly on top of Jose's commits, preserving original authorship (`Jose Luis Rivero <jrivero@honurobotics.com>`).
4. **Unified `extendable*` (`E*`) Validation Suite (Stages 1 $\to$ 6)**:
   - **Stages 1–3 (`extendable*`, Jobs `E*` — Pure CMake without Workspace Package)**: Pure CMake packages (`<build_type>cmake</build_type>`) isolating `binary_rule`, `install_rule`, `ReleaseAndSourceDependencyWalker` boundary pruning, pure-CMake underlay exports (`CMAKE_PREFIX_PATH`, `LD_LIBRARY_PATH` in `workspace.py`), and multi-tier/hybrid/diamond DAGs without a workspace package.
   - **Stages 4–5 (`extendable` & `extendablebin`, Jobs `E*` — Full `ros_workspace` Stack)**: Native ROS 2 `ament_cmake` + `ros_workspace` + `bloom` + `rosdistro_build_cache` lifecycle inside `E*` (requiring `ament_package`, `ament_cmake_core` with manual `PYTHONPATH` bootstrap patch, and `ros_workspace` in the root distro), adopting Jose's `BINARY_IMPORT_OVERRIDABLE = frozenset(['ros_workspace'])` in `rosdistro`, `ROS_WORKSPACE_PARENT_PREFIX_PATH` in `ros_workspace`, and `ParentPrefixes` in `bloom`.
   - **Stage 6 (`extendable*`, Jobs `E*` — Adopted `workspace_package` / `ros_workspace_shell` & ROS + Gazebo)**: Adopts Jose's `ros_workspace_shell` split (`a89cc7b`) and `workspace_package` key (`bc0600f` in `rosdistro`, `2cb93dc` in `bloom`, `146d05f` in `ros_buildfarm`) onto stacked `feat/rep159-workspace-package` branches (`5d4a392`, `aa5133e`, `e54594c` / `2bff39e`, `0905caa`), allowing non-ROS/Gazebo underlays to install `/opt/ros/<distro>/setup.bash` via a single plain-CMake package (`ros_workspace_shell`) with zero Ament dependencies.
